# UAT Guide

## 文档目标

这份文档用于指导下一轮 **基于 `apps/api` 唯一后端基线的体验优化 UAT**。

本轮验收不再重复聚焦上一轮已经确认通过的 P0 主链路问题，而是确认 2026-03-29 新增体验范围是否真正落地，并且没有回退当前预约主链路。

当前要验证的是：

1. 首页单张返图卡片 + “查看全部返图灵感”入口
2. `pages/gallery-list` 全部返图列表页
3. 返图详情多图体验
4. 顾客预约页月历化日期选择
5. 店员返图上传 / 标签 / 文字说明管理
6. 店员审核结果可修改后的行为一致性
7. 体验版登录链路使用 `wx.login + Bearer token`，不依赖 mock OpenID header

---

## 当前适用场景（2026-03-29）

当前项目已经完成：
- `apps/api` 作为唯一后端基线的收口
- 旧 `apps/server` 与过渡文档退场
- 上一轮页面级 P0 UAT 6 项通过
- `docs/PRD.md`、`docs/ARCHITECTURE.md`、`docs/API.md`、`docs/TASKS.md` 已冻结 2026-03-29 新范围

因此你现在如果要做验收，应理解成：

> **围绕“返图内容扩展 + 顾客月历 + 店员运营能力”做一轮新的页面级体验 UAT**

## 一、验收前准备

### 1. 启动后端

在项目根目录执行：

```bash
npm run dev:api
```

如果你只想按当前配置直接启动，也可以：

```bash
npm run start:api
```

默认接口地址：

```text
http://127.0.0.1:3100
```

### 2. 可选：先跑后端自测

```bash
npm run test:api
```

### 3. 打开微信开发者工具

- 打开目录：`apps/weapp`
- 确认开发环境请求基地址为：`http://127.0.0.1:3100`
- 确认当前前端已连接 `apps/api` 主线，而不是历史旧基线

### 4. 准备测试身份

#### 店员 OpenID

本地 UAT 建议使用：

```text
staff-openid-demo
```

#### 顾客 OpenID

开发环境建议使用稳定 mock 值，例如：

```text
customer-openid-demo
```

重点不是具体值，而是确认：
- 顾客请求头使用 `X-Customer-OpenId`
- 店员请求头使用 `X-Staff-OpenId`
- 顾客回查、店员返图管理、审核修改链路在同一组身份下可连续复现

### 5. 体验版登录检查

体验版 / 正式版不再使用 mock header 作为身份主链路，需额外确认：

- 小程序 profile 为 `trial` 或 `release`
- API 域名为 HTTPS
- `enableWechatAuth=true`
- `allowHeaderAuthFallback=false`
- Network 面板中顾客 / 店员接口带有 `Authorization: Bearer <token>`
- 不再出现 `X-Customer-OpenId` / `X-Staff-OpenId` 作为主身份头
- 店员 OpenID 已配置在服务端 `STAFF_OPEN_IDS`

## 二、建议验收顺序

建议按下面顺序执行：

1. 首页单张返图卡片 + 查看全部入口
2. 全部返图列表页 + 详情多图
3. 顾客预约页月历选日期 + 提交预约
4. 我的预约回查
5. 店员返图上传 / 创建 / 编辑
6. 店员修改审核结果
7. 顾客再次查看修改后的审核结果
8. 体验版登录 / 退出 / 无权限店员验证

如果时间有限，最低优先保证以下 4 项：

1. 全部返图列表页
2. 顾客月历选日期
3. 店员返图内容管理
4. 店员审核结果修改
5. 体验版不依赖 mock OpenID header

## 三、详细验收步骤

## Case 1：首页单张返图卡片 + 查看全部入口

### 操作
1. 打开首页 `pages/home`
2. 观察返图灵感区是否只展示最近 1 条已发布内容
3. 点击“查看全部返图灵感”入口

### 预期结果
- 首页不再堆出全部返图
- 默认只展示最近 1 条已发布内容
- “查看全部返图灵感”入口可见、可点击
- 点击后进入 `pages/gallery-list`

### 若失败，记录什么
- 是展示数量不对、入口缺失，还是跳转失败
- 当前首页展示的返图标题
- 截图

---

## Case 2：全部返图列表页

### 操作
1. 进入 `pages/gallery-list`
2. 观察列表布局与内容顺序
3. 点击任意一条返图

### 预期结果
- 列表按 `publishedAt desc` 展示全部已发布返图
- 列表为封面卡片流，不在列表页直接展开多图
- 点击后进入现有详情页
- 整体风格保持当前项目品牌感，不变成后台表格感

### 若失败，记录什么
- 是排序不对、内容不全，还是点击无效
- 当前点击的返图标题
- 截图

---

## Case 3：返图详情多图

### 操作
1. 从首页或列表页进入任意返图详情
2. 观察详情图集

### 预期结果
- 可展示该返图的多张图片
- 若 `imageUrls` 缺失，也至少会用封面图兜底
- 标题、说明、标签等信息与列表页 / 管理页口径一致

### 若失败，记录什么
- 是详情空白、只显示一张图，还是说明信息缺失
- 当前返图标题
- 截图

---

## Case 4：顾客月历选日期 + 时间段说明

### 操作
1. 进入 `pages/booking`
2. 观察日期选择区是否为月历视图
3. 点击不同日期
4. 选择一个可预约时间段并提交预约

### 预期结果
- 顾客端不再只使用横向日期条，而是使用月历视图
- 月历日期格能直观看到可约 / 已满 / 闭店 / 超窗等状态
- 点击日期会刷新该日时间段
- 时间段继续显性展示可约 / 不可约原因
- 提交成功后生成 `pending` 预约

### 若失败，记录什么
- 是月历没出现、状态看不懂，还是选日后不刷新
- 当前点击日期
- 截图

---

## Case 5：我的预约回查（回归项）

### 操作
1. 进入 `pages/my-bookings`
2. 使用与 Case 4 相同的顾客身份刷新页面

### 预期结果
- 能查到刚刚创建的预约
- 状态展示不回退
- 顾客仍按 OpenID 回查，不回退到手机号主查

### 若失败，记录什么
- 是查不到记录、状态错误，还是接口报错
- 当前顾客 OpenID（或 mock 值）
- 截图

---

## Case 6：店员返图上传与内容管理

### 操作
1. 进入 `pages/staff/gallery`
2. 输入店员 OpenID：`staff-openid-demo`
3. 上传 2~3 张图片
4. 填写标题、文字说明、标签
5. 选择封面图并发布或保存
6. 返回顾客侧首页 / 列表页检查是否可见

### 预期结果
- 图片上传成功，并返回可用图片 URL
- 店员可维护封面图、多图、标签、说明、发布时间 / 状态
- 顾客侧首页 / 列表页能读取已发布内容
- 不出现“图片上传成功但返图记录没保存”或“返图记录已保存但图片失效”的割裂体验

### 若失败，记录什么
- 是上传失败、保存失败，还是顾客侧不显示
- 当前返图标题
- 截图

---

## Case 7：店员审核结果修改

### 操作
1. 在 `pages/staff/appointments` 中找到一条已审核预约
2. 将其从“已通过”改成“已拒绝”，或从“已拒绝”改成“已通过”
3. 如有需要填写 `reviewNote`

### 预期结果
- 已审核记录允许再次修改结果
- 改回 `approved` 时，若该时段已被其他通过预约占用，应给出明确冲突提示
- 改成 `rejected` 后，应释放该时段占用
- 页面提示清晰，不让店员误以为操作已成功但实际未生效

### 若失败，记录什么
- 是按钮不可操作、接口报错，还是状态没刷新
- 是否出现 `SLOT_OCCUPIED` 等提示
- 截图

---

## Case 8：顾客查看修改后的审核结果

### 操作
1. 回到 `pages/my-bookings`
2. 使用同一顾客身份刷新页面

### 预期结果
- 顾客能看到最新一次审核结果
- 若审核备注被修改，顾客侧也能看到最新内容
- 顾客侧状态与店员端当前状态一致

### 若失败，记录什么
- 当前顾客身份
- 目标预约记录
- 截图

## 四、可选补充验证

## Case 9：体验版登录与权限

### 操作
1. 使用体验版打开小程序
2. 进入顾客预约页，触发微信登录
3. 打开 Network 面板检查请求头
4. 使用非店员账号进入店员页
5. 使用店员账号进入店员页
6. 调用退出登录能力后重新进入页面

### 预期结果
- 顾客 / 店员接口使用 `Authorization: Bearer <token>`
- 体验版不依赖 mock OpenID header
- 非店员账号访问 staff 接口返回 `STAFF_UNAUTHORIZED`
- 店员账号可访问 staff 页面
- 退出登录后旧 token 失效，再访问 `/api/v1/auth/me` 返回 `SESSION_UNAUTHORIZED`

### 若失败，记录什么
- 当前小程序环境版本
- Network 请求头
- 服务端返回错误码
- 截图

## Case 10：接口口径一致性（防回退）

### 操作
1. 打开微信开发者工具 Network 面板
2. 跑一轮：首页 -> 列表 -> 详情 -> 预约 -> 我的预约 -> 店员返图管理 -> 店员审核修改

### 预期结果
- 请求主线集中在当前冻结契约：
  - `/api/v1/gallery`
  - `/api/v1/availability`
  - `POST /api/v1/appointments`
  - `GET /api/v1/my/appointments`
  - `/api/v1/staff/uploads/images`
  - `/api/v1/staff/gallery`
  - `/api/v1/staff/appointments/*`
- 不应再看到旧接口或前端自造字段

## 五、本轮通过标准

本轮可以认为“页面级体验 UAT 通过”的最低标准：

- 首页单张返图卡片 + 查看全部入口正常
- 全部返图列表页可用，详情多图正常
- 顾客预约页已切到月历式日期选择，且状态表达清晰
- 店员可上传并维护返图内容
- 店员可修改已审核结果，顾客侧能看到最新状态
- 体验版身份链路使用微信登录 Bearer token，不依赖 mock OpenID header
- 上述新增体验不回退当前顾客预约 / 我的预约主链路
